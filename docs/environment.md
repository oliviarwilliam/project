# Environment variables

Set these in Render (Environment tab) or in `.env.local` for local work. The app checks them when it starts. In production it refuses to start if a required one is missing, so a bad deploy fails loudly instead of half working.

## Public, compiled into the browser bundle
These end up in the JavaScript sent to every visitor. They are not secret, and they are read at **build** time, so changing one needs a redeploy.

| Name | Required | Example | Notes |
| --- | --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | yes | `https://app.example.com` | Must start with `https://` in production, no trailing slash. Used for email links, the Paystack return URL and the CSRF origin check. |
| `NEXT_PUBLIC_SUPABASE_URL` | yes | `https://abcd.supabase.co` | Supabase, Project Settings, API. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | yes | `eyJ...` | Supabase "anon public" key. Safe in the browser because row level security guards the data. |

## Secrets, server only
Never prefix these with `NEXT_PUBLIC_`, never commit them, never paste them in chat or tickets.

| Name | Required | Where to get it | Used for |
| --- | --- | --- | --- |
| `SUPABASE_SERVICE_ROLE_KEY` | yes | Supabase, Project Settings, API ("service_role") | Wallet functions, admin features, rate limiting, audit. **Bypasses row level security.** Rotate it if it ever leaks. |
| `PAYSTACK_SECRET_KEY` | yes | Paystack, Settings, API Keys | Initialising and verifying payments, bank transfers, webhook signatures. Use `sk_test_` until launch, `sk_live_` after. |
| `CRON_SECRET` | yes | Generated by Render (`render.yaml`) | Bearer token for `/api/cron/*`. At least 32 characters. Copy this value into Supabase Vault as `teenvest_cron_secret` so Supabase can call the transfer job. |

## Behaviour switches
| Name | Default | Notes |
| --- | --- | --- |
| `PAYSTACK_TRANSFERS_ENABLED` | `false` | Kill switch for automatic bank payouts. Set `true` only after the launch checklist. |
| `CSP_MODE` | `report-only` | `report-only` logs violations to `/api/csp-report`. `enforce` blocks them. Switch after a clean smoke test. |
| `TRUSTED_PROXY_HOPS` | `1` | Number of proxies in front of the app. Used to find the real client address for rate limits. |
| `CLIENT_IP_HEADER` | unset | If your proxy sets a header with the true client address (for example `cf-connecting-ip` behind Cloudflare), name it here. Only set it when the proxy overwrites that header, otherwise clients can fake it. |
| `ALLOWED_ORIGINS` | unset | Extra origins allowed to send data-changing requests, comma separated. Add the `*.onrender.com` address if you use both it and a custom domain. |
| `RATE_LIMIT_DISABLED` | unset | `true` switches rate limits off for local testing. The app refuses to start with it in production. |

## Platform
| Name | Where | Notes |
| --- | --- | --- |
| `NODE_VERSION` | Render | `22`. Also in `.nvmrc` and `engines`. |
| `NODE_ENV` | Render sets it | `production` at runtime. |
| `APP_URL` | — | Not needed by the web service. Store the Render app URL in Supabase Vault as `teenvest_app_url` for the transfer schedule. |

## Rotation
1. Create the new value (new Supabase key, new Paystack key, new `CRON_SECRET`).
2. Update `CRON_SECRET` in Render and update `teenvest_cron_secret` in Supabase Vault to the same value.
3. Redeploy. Check `/api/health`, then a test payment and the Supabase scheduled job history.
4. Revoke the old value. Rotate immediately if a secret appears in a log, a screenshot or a commit.
